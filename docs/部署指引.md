## ✅ 线上部署：Cloudflare Pages

**线上链接（报名表填写）**：

# https://yingzao.pages.dev/

- 部署方式：Wrangler CLI 直传 `dist`，项目名 `yingzao`
- Cloudflare 账号已通过 OAuth 授权（本机 wrangler 凭据）
- 报名表链接优先级：主链接 `https://yingzao.pages.dev/`；若网评环境打不开，用**离线单文件版**（见下）

### 更新方法（改代码后必做）

```bash
cd D:\比赛4\yingzao
npm run build
wrangler pages deploy dist --project-name=yingzao --branch=main --commit-dirty=true
```

- `--commit-dirty=true` **必须加**：工作区有未提交改动时，不加会交互式询问，在非交互环境（脚本 / 自动化）下会挂住
- 成功后输出形如 `✨ Deployment complete! https://<hash>.yingzao.pages.dev`；`--branch=main` 表示进生产环境
- 回滚 / 自定义域名：登录 dash.cloudflare.com 可见 `yingzao` 项目

## ⚠️ 改源码后的「强制同步」纪律

**改源码后必须同步下面全部环节**，漏任何一处都会出现「线上 / 提交包 / 参赛 PPT」三者不一致。

### 一键同步（推荐）

已提供编排脚本 `scripts/sync-all.mjs`，把下面的 8 步串成一条命令，每步带校验、失败即停：

```bash
cd D:\比赛4\yingzao
npm run sync              # 跑全部 8 步
npm run sync -- --dry     # 只打印将执行的命令，不实际运行
npm run sync -- --no-deploy   # 跳过部署（等线上核验时）
npm run sync -- --from=3  # 从第 3 步开始（前 2 步已完成）
npm run sync -- --only=5  # 只跑第 5 步
```

> 第 4、8 步是**人工判断项**（文档是否涉改、AI 记录是否补写），脚本会自动提示。

### 手动清单（脚本每一步做什么）

按顺序逐项：

| # | 动作 | 产物 / 位置 |
|---|---|---|
| 1 | `npm run build` | `dist/`（线上用） |
| 2 | `wrangler pages deploy dist --project-name=yingzao --branch=main --commit-dirty=true` | 线上链接（**部署后必做自检**，见上节） |
| 3 | `npx vite build --config vite.singlefile.config.ts` → 把 `dist-single/index.html` 复制为 `营造-提交包/大木作-离线单文件版.html` | 提交包离线版 |
| 4 | `node scripts/recapture-ppt-shots.mjs <url> <outdir>` 重截应用截图 → 替换 `答辩PPT.pptx` 内嵌图 | 参赛 PPT |
| 5 | 检查 `设计说明文档.docx/.pdf` 是否含涉改数据 / 图示；有则改并**重导 PDF + 复查目录页码** | 提交包文档 |
| 6 | `python scripts/make-submission-zip.py` 重建 `营造-提交包.zip`（**排除 PPT**） | 报名第 10 项 |
| 7 | 同步 `yingzao/docs/` 内交付物副本（与 `营造-提交包/` 两边一致） | 仓库副本 |
| 8 | 推送源码（`python docgen/push-via-gh.py`，改 commit message）；必要时同步 Gitee 镜像 | GitHub / Gitee |

> **第 4 步是重灾区**：只要界面有可见变化（文案、配色、布局、数值）就必须重截，
> 否则 PPT 里的截图还是旧界面。截图脚本预置 localStorage 须**同时**设
> `yingzao-session-v1` 与 `yingzao-tutorial-v2-done=1`，否则教程浮层会盖住画面。

**提交源码**（git 直推不通时）：

```bash
cd D:\比赛4\yingzao
git add <新增文件>          # 新增文件必须先 add，否则不会被推送
python docgen/push-via-gh.py
```

> 说明：`git fetch/push` 直连会报 `invalid index-pack output`，且本地与远程历史可能已分叉。
> `docgen/push-via-gh.py` 走 gh CLI + GitHub Git Data API（blobs→tree→commit→ref），只上传 `git ls-files` 列出的**源码**，不含构建产物。
> **注意**：该脚本只增改、**不删除**文件；若需删远程文件，用 Contents API
> `gh api repos/<owner>/<repo>/contents/<path> --method DELETE -f message=... -f sha=<blob sha>`。

## 离线兜底（现场答辩必备）

### 首选：单文件 HTML

`营造-提交包/大木作-离线单文件版.html` —— **整个作品内联在一个文件里，双击即用**，无需 Node、无需服务器、无需联网。

- 生成：`npx vite build --config vite.singlefile.config.ts`（输出 `dist-single/index.html`）
- 已验证：零外部请求（无 CDN / 无外链字体），断网可运行
- **首次打开需先注册账号**（用户名 2–16 位、密码至少 4 位）再登录；账号只存在本机浏览器，换机器需重新注册

### 备选：dist + 本地服务器

```bash
cd D:\比赛4\yingzao
npm run build
cd dist && python -m http.server 8080
# 浏览器打开 http://localhost:8080
```

也可双击项目根目录的 `启动.bat` 选离线模式（需 Node.js）。

## 常见问题排查

| 现象 | 原因 | 解决 |
|---|---|---|
| pages.dev 打不开 | 地区网络对该域名的解析波动 | 手机流量测试；或直接用离线单文件版 |
| 链接能开但点「进入」没反应 | 浏览器禁用了 localStorage（隐私模式） | 换普通模式 |
| 首次打开卡在登录页 | 未注册账号 | 点「注册」新建账号后登录 |
| 三维画面卡顿 | 集显 / 低配设备 | 缩小浏览器窗口；关闭其他标签页；移动端本就会降档 |
| 抗震演示没有震动 | 未点「开始震动」，或震级滑杆停在 1 级 | 点按钮；预设选「中震」（7 级）以上 |
| 转视角时老是选中构件 | （已修复）旧版点击判定绑在 `pointerdown` | 确保用的是最新构建 |

仓库 `gitee.com/jingdanxiushi/yingzao-pages` —— 构建产物的静态镜像（master 分支）。

  仅作为「正式站点不可达时的代码可见链接」备查
- **当前状态**：2026-10-09 已同步至《大木作》最新构建（commit `b9824ee`）

**更新方法**（改源码后可选；需 Gitee 私人令牌，`gitee.com/profile/personal_access_tokens` 勾 `projects`）：

```bash
git clone https://<用户名>:<令牌>@gitee.com/jingdanxiushi/yingzao-pages.git /tmp/mirror
cd /tmp/mirror
rm -rf assets index.html
cp -r D:/比赛4/yingzao/dist/* .
git config core.autocrlf false          # 关键：否则 LF 会被转成 CRLF，产物与 dist 不再逐字节一致
git add -A && git commit -m "deploy: 构建产物镜像同步"
git push origin master
```

- **令牌不要写进任何文件**；用完立即到 gitee.com/profile/personal_access_tokens 删除
